# SPEC.md

## 앱 목적

개인 식단 관리 앱은 사용자가 하루 식단을 아침, 점심, 저녁 단위로 계획하고, 실제로 먹은 음식을 체크해 하루 영양 섭취 현황을 확인할 수 있게 하는 모바일 앱이다.

1차 배포 목표는 Android/iOS에서 동작하는 Expo React Native + TypeScript 기반 MVP를 완성하는 것이다. 음식 검색은 공공데이터 식품영양성분 정보를 조회하는 구조로 설계한다.

## MVP 범위

- 아침, 점심, 저녁 식단 생성 및 수정
- 식단별 음식 추가, 삭제
- 음식 섭취 여부 체크
- 하루 단위 영양 섭취 합계 표시
- 음식명 기반 검색
- 공공데이터 식품영양성분 정보 조회
- 검색 결과에서 음식 선택 후 섭취 g수 입력
- 칼로리, 탄수화물, 단백질, 지방, 당류, 나트륨 등 주요 영양성분 표시
- 로컬 저장소를 통한 최근 식단 데이터 보존
- 영양정보 참고용 고지 표시
- Android/iOS 1차 배포에 필요한 기본 앱 설정 및 빌드 검증

## 데이터 모델

### MealType

식사 구분이다.

- `breakfast`
- `lunch`
- `dinner`

### Nutrition

음식 또는 하루 합산 영양성분 값이다. 각 영양성분 필드는 `number | null`로 관리한다.

- `number`: 공공데이터에서 유효한 숫자로 제공됐거나, 유효한 숫자를 기준으로 계산된 값
- `null`: 공공데이터에 값이 없거나, 값이 숫자로 신뢰 가능하게 변환되지 않거나, 계산 기준이 없어 산출할 수 없는 값

정규화가 끝난 앱 내부 모델과 저장 데이터에는 `undefined`를 남기지 않는다. API 응답 파싱 중 `undefined`가 발생하면 저장 전 `null`로 변환한다.

| 필드 | 타입 | 단위 | 설명 |
| --- | --- | --- | --- |
| `caloriesKcal` | number \| null | kcal | 열량 |
| `carbohydrateG` | number \| null | g | 탄수화물 |
| `proteinG` | number \| null | g | 단백질 |
| `fatG` | number \| null | g | 지방 |
| `sugarsG` | number \| null | g | 당류 |
| `sodiumMg` | number \| null | mg | 나트륨 |
| `fiberG` | number \| null | g | 식이섬유 |
| `saturatedFatG` | number \| null | g | 포화지방 |
| `transFatG` | number \| null | g | 트랜스지방 |
| `cholesterolMg` | number \| null | mg | 콜레스테롤 |

### 결측값 표현 규칙

- 실제 `0`은 유효한 숫자 값이다. 공공데이터가 명시적으로 `0`, `0.0`, `0mg`, `0g` 등을 제공하면 `0`으로 저장하고 합산에 포함한다.
- `null`은 결측값이다. 값이 없거나 숫자로 변환할 수 없거나 단위가 불명확하면 `null`로 저장한다.
- `undefined`는 앱 내부 정규화 완료 후 허용하지 않는다. 발견되면 `null`과 동일하게 처리하고 저장 전 `null`로 치환한다.
- 빈 문자열, 공백 문자열, `-`, `N/A`, `NA`, `n/a`, `null` 문자열, 실제 `null`, 실제 `undefined`는 모두 결측값으로 본다.
- 숫자와 단위가 함께 온 문자열은 단위가 기대 단위와 일치할 때만 숫자로 파싱한다. 예: `100g`은 g 필드에서 `100`으로 변환 가능하지만, 단위를 확정할 수 없는 값은 `null`로 처리한다.
- 음수 영양성분 값은 유효하지 않은 값으로 보고 `null`로 처리한다.

### Food

공공데이터 또는 사용자가 선택한 음식의 기준 정보다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `id` | string | 앱 내부 음식 ID |
| `source` | string | `public_food_nutrition` 등 데이터 출처 |
| `sourceFoodId` | string | 공공데이터 원본 식품 ID 또는 식별 가능한 키 |
| `name` | string | 음식명 |
| `brandName` | string \| null | 제조사, 업체명, 브랜드명 |
| `category` | string \| null | 식품 분류 |
| `servingSize` | number \| null | 기준 제공량. 공공데이터에 없거나 신뢰할 수 없으면 `null` |
| `servingUnit` | string \| null | g, ml, serving 등. 기준 제공량 단위를 확정할 수 없으면 `null` |
| `nutritionPerServing` | Nutrition | 기준 제공량당 영양성분. 개별 영양성분은 `null`일 수 있음 |
| `updatedAt` | string | 앱에 저장된 시각, ISO 8601 |

MVP에서는 `servingSize`가 `null`이거나 `servingSize <= 0`이거나 `servingUnit`이 `null`인 음식은 비례 계산 기준이 없으므로 식단 추가를 제한한다. 현재 섭취량 입력은 g 단위로 고정하므로 `servingUnit`이 `g`가 아닌 음식도 자동 비례 계산 대상에서 제외한다. 검색 결과에는 "제공량 정보 없음" 또는 "추가 불가"를 표시한다. 이후 버전에서 사용자가 기준 제공량과 영양성분을 직접 입력하는 흐름을 추가할 수 있다.

### MealFood

식단에 추가된 음식 항목이다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `id` | string | 식단 음식 항목 ID |
| `foodId` | string | 연결된 음식 ID |
| `mealId` | string | 연결된 식단 ID |
| `consumedGrams` | number | 사용자가 입력한 섭취 g 수. 같은 식단 내 동일 `foodId` 병합 시 합산된다. |
| `checked` | boolean | 실제 섭취 여부 |
| `calculatedNutrition` | Nutrition | `consumedGrams` 기준으로 조정된 영양성분. 계산할 수 없는 영양성분은 `null` |
| `createdAt` | string | 생성 시각, ISO 8601 |
| `updatedAt` | string | 수정 시각, ISO 8601 |

같은 `mealId` 안에 같은 `foodId`가 이미 있으면 새 줄을 만들지 않고 기존 항목의 `consumedGrams`에 새 입력 g 수를 더한다. 병합 대상 중 하나라도 `checked: true`이면 병합 후 항목도 `checked: true`를 유지한다. 병합 후 `calculatedNutrition`은 합산된 `consumedGrams` 기준으로 다시 계산한다.

## 공공데이터 API 연동 방식

### 데이터 출처

MVP의 기본 데이터 출처는 공공데이터포털에서 제공하는 식품영양성분 관련 Open API로 한다. 실제 구현 전 API 제공 기관, 엔드포인트, 인증 방식, 요청 제한, 응답 필드명은 공공데이터포털의 최신 문서에서 확인한다.

후보 데이터셋:

- 식품의약품안전처 또는 관계 기관의 식품영양성분 DB
- 음식명, 식품명, 제조사, 1회 제공량, 열량, 탄수화물, 단백질, 지방, 당류, 나트륨을 제공하는 공공데이터 API

### 연동 구조

- 앱은 `FoodSearchService`를 통해 음식 검색을 요청한다.
- `FoodSearchService`는 공공데이터 응답을 앱 내부 `Food` 모델로 변환한다.
- 공공데이터 원본 필드명은 화면 또는 도메인 로직에서 직접 사용하지 않는다.
- API 장애, 응답 지연, 결과 없음, 필드 누락은 명시적인 상태로 처리한다.
- 검색어는 최소 1자 이상 입력 시 요청 가능하게 하되, 실제 요청은 debounce를 적용한다.
- 같은 검색어에 대한 결과는 짧은 시간 동안 캐시할 수 있다.

### API 키 관리

공공데이터 API 키는 모바일 앱 번들에 직접 포함하지 않는 것을 원칙으로 한다.

권장 구조:

- 앱: 검색어와 페이지 정보를 백엔드 프록시 또는 서버리스 함수에 요청
- 프록시: 공공데이터 API 키를 안전하게 보관하고 원본 API 호출
- 프록시: 필요한 필드만 정규화해 앱에 반환

초기 개발 중 임시로 클라이언트에서 직접 호출할 수는 있으나, 1차 배포 전에는 API 키 노출 위험을 제거해야 한다.

### 응답 정규화

공공데이터 응답은 다음 기준으로 정규화한다.

- 숫자 필드는 문자열로 오더라도 유효한 숫자로 파싱해 `number`로 저장한다.
- 빈 문자열, 공백 문자열, `null`, `undefined`, `-`, `N/A`, `NA`, `n/a`, `null` 문자열은 `null`로 저장한다.
- 실제 `0`과 결측값은 반드시 구분한다. `0`은 합산 가능한 값이고, `null`은 합산에서 제외되는 값이다.
- 숫자 변환에 실패한 값, 음수 값, 기대 단위와 맞지 않는 값은 `null`로 저장한다.
- 단위가 명확하지 않은 필드는 계산에 사용하지 않고 화면에 "정보 없음"으로 표시한다.
- 기준 제공량이 없거나 0 이하인 음식은 `servingSize: null`, 기준 단위가 없으면 `servingUnit: null`로 저장하고 MVP에서는 식단 추가를 제한한다.
- 동일 음식명이 여러 개일 수 있으므로 제조사, 분류, 기준량을 함께 표시한다.

## 영양성분 계산 규칙

### 기본 원칙

- 하루 섭취 현황은 체크된 음식만 합산한다.
- 예정 섭취량은 체크 여부와 관계없이 식단에 추가된 모든 음식을 합산한다.
- 사용자가 입력한 `consumedGrams`가 기준 제공량과 다르면 비례 계산한다.
- 계산 결과는 참고용이며 의학적 판단이나 처방으로 사용하지 않는다.

### 계산식

기준 제공량당 영양성분이 있고 `servingSize > 0`인 경우:

```text
adjustedNutrition = baseNutrition * (consumedGrams / servingSize)
```

`baseNutrition`의 특정 필드가 `null`이면 `adjustedNutrition`의 해당 필드도 `null`로 유지한다.

예:

```text
기준 제공량: 100 g
기준 열량: 250 kcal
사용자 입력 섭취량: 150 g
계산 열량: 250 * (150 / 100) = 375 kcal
```

### 반올림

- kcal: 소수점 첫째 자리에서 반올림해 정수 표시
- g 단위 영양성분: 소수점 첫째 자리까지 표시
- mg 단위 영양성분: 소수점 첫째 자리에서 반올림해 정수 표시
- 내부 계산은 원본 숫자를 유지하고, 화면 표시 시에만 반올림한다.

### 누락값 처리

- 특정 영양성분 값이 `null` 또는 `undefined`이면 해당 필드는 합산에서 제외한다.
- 합산 중 일부 음식만 해당 영양성분 값이 `null`이면, 값이 있는 음식만 합산하고 해당 필드를 `missingNutritionFields`에 기록한다.
- 합산 대상 음식의 특정 영양성분이 모두 `null`이면 합계도 `null`로 둔다.
- 실제 `0`은 합산에 포함한다. `0`만 있는 합계는 `0`으로 표시한다.
- UI에서 `null` 합계는 "정보 없음"으로 표시한다.
- UI에서 일부 결측값이 포함된 합계는 숫자와 함께 "일부 음식 정보 없음" 안내를 표시한다.
- 필수 표시 항목 중 개별 음식 값이 `null`이면 "정보 없음"으로 표시한다.

### 단위 처리

- g, ml, serving 등 원본 단위를 보존한다.
- 현재 MVP의 섭취량 입력 UI는 g 단위 숫자 입력으로 고정한다.
- 기준 제공량과 사용자 입력 단위가 다르면 자동 변환하지 않는다.
- MVP에서는 `servingUnit`이 `g`인 음식만 g 입력값으로 비례 계산한다.
- 단위가 다른 경우 이후 버전에서 기준 단위 입력 또는 단위 변환 흐름을 제공한다.

## 1차 배포 기준

1차 배포는 다음 조건을 만족해야 한다.

- Android와 iOS에서 앱 실행 가능
- TypeScript 오류 없음
- 주요 화면 이동 가능
- 아침, 점심, 저녁 식단 생성 및 음식 추가 가능
- 음식 섭취 체크 시 하루 영양 섭취 현황 갱신
- 공공데이터 기반 음식 검색 가능
- API 장애 또는 결과 없음 상태 처리
- 로컬 저장소에 식단 데이터 보존
- 영양정보 참고용 고지 노출
- 의료/질병 진단 표현 없음
- 앱 아이콘, 스플래시, 앱 이름 등 기본 배포 메타데이터 설정
- Expo 빌드 또는 스토어 제출 전 빌드 검증 완료

## 영양정보 참고용 고지

앱 내 영양정보는 공공데이터와 사용자가 입력한 섭취량을 기반으로 계산한 참고용 정보다. 실제 제품, 조리 방식, 제공량, 제조사 정보, 데이터 갱신 시점에 따라 실제 영양성분과 차이가 있을 수 있다.

앱은 건강 상태 판단, 질병 진단, 치료, 처방, 식이요법 지시를 제공하지 않는다. 건강 문제나 식단 제한이 있는 사용자는 의료 전문가와 상담해야 한다.

## 의료/질병 진단 표현 금지

앱 화면, 문구, 알림, 도움말, 마케팅 문구에서는 다음 표현을 사용하지 않는다.

- 특정 질병을 진단한다는 표현
- 질병을 치료하거나 예방한다는 표현
- 의사, 영양사, 의료기관 상담을 대체한다는 표현
- 사용자 건강 상태를 정상/비정상으로 판정하는 표현
- 약물 복용, 치료, 임상적 식이요법을 지시하는 표현

허용되는 표현은 다음 범위로 제한한다.

- "영양정보는 참고용입니다."
- "섭취량 계산은 입력값과 데이터 출처에 따라 달라질 수 있습니다."
- "건강 관련 결정은 전문가와 상담하세요."
- "오늘 체크한 음식 기준 섭취량입니다."
